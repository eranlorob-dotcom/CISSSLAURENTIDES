Google Earth Engine (GEE) est un catalogue de plusieurs pétaoctets d'imagerie satellite et de données géospatiales, couplé à une puissance de calcul infonuagique. Pour la santé publique, c'est la porte d'accès aux indicateurs d'environnement dérivés de satellite : verdissement, îlots de chaleur, occupation du sol, qualité de l'air — à l'échelle des Laurentides comme du Québec entier.

▸ Qu'est-ce que GEE

On n'y « télécharge » pas des fichiers d'abord : on écrit une requête, le calcul s'exécute sur les serveurs de Google, et on récupère seulement le résultat (une carte, une statistique, ou un fichier exporté). Deux environnements donnent accès à la même API :

Code Editor (JavaScript)

Un éditeur web à code.earthengine.google.com : on écrit du JavaScript, on voit la carte et les résultats immédiatement. Idéal pour apprendre et prototyper.

API Python (+ geemap)

La bibliothèque earthengine-api, souvent avec geemap pour l'affichage, dans un carnet Jupyter ou Colab. Idéal pour intégrer GEE à un flux d'analyse existant.

1 Accès & admissibilité

Depuis 2025, l'accès passe par un projet Google Cloud avec l'API Earth Engine activée, qu'il faut enregistrer comme usage commercial ou non commercial. L'inscription se fait sur la page d'enregistrement.

⚠ Point crucial pour un organisme public (CISSS)

GEE est gratuit pour la recherche, l'enseignement, le milieu à but non lucratif et la formation. Mais l'usage gratuit par un organisme gouvernemental (ce qu'est un CISSS) est plus encadré : il est permis pour la recherche savante, mais pas pour le développement interne, le prototypage à des fins internes, la production répétée de produits de données, ni le maintien continu d'applications ou de services. Ces usages opérationnels exigent une licence commerciale.

Concrètement : pour cette formation et pour de la recherche, l'accès gratuit convient. Pour bâtir une surveillance environnementale opérationnelle et récurrente à la DSP, vérifiez l'admissibilité avant de vous appuyer sur GEE. L'accès gouvernemental est aussi sujet à révision par Google et doit utiliser un compte Google institutionnel, pas personnel.

Étapes d'inscription (usage non commercial)

1. Créer ou choisir un projet Google Cloud   2. Activer l'API Earth Engine   3. Enregistrer le projet comme non commercial (type : formateur / participant à une formation, ou recherche)   4. Confirmer l'admissibilité   5. Ouvrir le Code Editor.

Aucun compte de facturation n'est requis pour un projet non commercial admissible.

code.earthengine.google.com/register  ·  règles d'usage non commercial

Le palier Community (par défaut, ~150 EECU-h/mois) suffit pour apprendre et faire de petites analyses ; les paliers supérieurs demandent une vérification d'identité par compte de facturation. 2 Premiers pas — Code Editor

Un exemple concret et pertinent : calculer le verdissement (NDVI) de l'été sur les Laurentides à partir de Sentinel-2. Le NDVI est un proxy d'espaces verts, associé à des bénéfices de santé (chaleur, activité physique, santé mentale).

// 1. Définir la zone d'intérêt (Laurentides, approx.)
var laurentides = ee.Geometry.Rectangle([-75.5, 45.5, -73.3, 47.2]);

// 2. Composite Sentinel-2 estival, peu nuageux
var s2 = ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
  .filterBounds(laurentides)
  .filterDate('2024-06-01', '2024-09-01')
  .filter(ee.Filter.lt('CLOUDY_PIXEL_PERCENTAGE', 20))
  .median();

// 3. Calculer le NDVI = (PIR - Rouge) / (PIR + Rouge)
var ndvi = s2.normalizedDifference(['B8', 'B4']).rename('NDVI');

// 4. Afficher
Map.centerObject(laurentides, 8);
Map.addLayer(ndvi, {min: 0, max: 0.8, palette: ['white', 'green']}, 'NDVI été 2024');

On colle ce code dans le Code Editor, on clique Run, et la carte de verdissement apparaît. On change les dates, la zone ou le seuil de nuages, et on relance.

4 Exporter vers vos outils

C'est le pont vers le reste de la formation. GEE exporte des rasters (GeoTIFF), des vecteurs (Shapefile, GeoJSON) et des tables (CSV) vers Google Drive, Google Cloud Storage ou comme actif Earth Engine. On rapatrie ensuite le fichier dans QGIS (Module 2) ou dans une carte Leaflet (Module 3).

// Exporter le NDVI en GeoTIFF vers Google Drive
Export.image.toDrive({
  image: ndvi.clip(laurentides),
  description: 'NDVI_Laurentides_2024',
  region: laurentides,
  scale: 10,          // résolution en mètres
  maxPixels: 1e10
});
// Puis onglet « Tasks » → Run. Le fichier arrive dans Drive.

Pour extraire une statistique par territoire (p. ex. NDVI moyen par RLS), on charge ses polygones comme FeatureCollection, on applique reduceRegions, puis Export.table.toDrive en CSV ou GeoJSON — prêt à joindre à vos autres données.

5 Python & geemap

Pour intégrer GEE à un carnet Python (Colab, Jupyter), l'authentification et l'initialisation se font en deux lignes, en précisant votre projet Cloud :

import ee, geemap
ee.Authenticate()
ee.Initialize(project='mon-projet-ee')

import geemap
m = geemap.Map(center=[46.2, -74.4], zoom=8)
ndvi = (ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
        .filterDate('2024-06-01', '2024-09-01')
        .median().normalizedDifference(['B8', 'B4']))
m.add_layer(ndvi, {'min': 0, 'max': 0.8, 'palette': ['white', 'green']}, 'NDVI')
m

6 Bonnes pratiques

Découper (clip) sur la zone d'intérêt le plus tôt possible : moins de pixels = calcul plus rapide et moins de quota consommé.

Choisir une échelle (scale) réaliste : inutile d'exporter à 10 m si on cartographie par RLS ; agréger d'abord.

Filtrer les nuages et composer sur une période (médiane saisonnière) plutôt qu'une image unique.

Surveiller le quota (palier Community) : les exports lourds se planifient, pas se répètent à l'aveugle.

Créditer les données (Copernicus/ESA, NASA, USGS…) selon la licence de chaque jeu.

Attention à l'inférence santé : une donnée satellite décrit l'environnement, pas les personnes. Le NDVI d'un secteur n'est pas l'exposition réelle de chaque résident — mêmes prudences écologiques que pour l'indice de défavorisation.

Enchaînement naturel avec la formation : GEE produit l'indicateur environnemental → export GeoJSON/GeoTIFF → QGIS pour la jointure (Module 2) → Leaflet pour la carte web (Module 3).
